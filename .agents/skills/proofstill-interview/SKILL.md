# 요구사항 인터뷰

- 긴 제공 명세가 있으면 기존 `requirements.md` 또는 동등한 문서의 요구 ID·원문 근거를 재사용한다. 인터뷰는 새 기획의 필수 관문이 아니다. 데이터에서 발견한 불일치와 미정 업무 조건만 질문하고 명확한 범위의 구현은 계속한다.
- 담당자 답변은 실제 출처와 함께 해당 요구 ID의 조건·기대 결과에 반영한다. 기존 요구와 충돌하면 차이와 영향을 드러내고 결정받는다. 추가 요청 때 전체 인터뷰를 다시 시작하지 않는다. 담당자 연락은 허용된 도구와 위임 범위에서 수행하며 연결 수단이 없으면 사용자에게 질문을 전달한다.

- 브리핑 전에 원래 요청과 관련 자료·기존 동작을 읽는다. 조사로 확인할 사실은 직접 확인하고, 사용자 의도·우선순위·허용할 결과가 필요한 결정만 질문한다. 이미 명확한 요구를 반복 확인하지 않는다.
- 기획자 역할은 무엇을 왜 만들고 어떤 결과를 수용할지 정제하는 것이다. 모호함이 실제 범위·행동·검증에 영향을 주는지 구체적인 사용 상황으로 확인한다. 구현 기술·추상적인 미래 확장 질문으로 인터뷰를 늘리지 않는다.
- 한 번에 중요한 질문 1~3개를 묻는다. 가능한 선택지와 차이, 추천 이유를 짧게 제시하고 자유 답변을 허용한다. 목적·사용자·사용 흐름·포함/제외 범위·완료 조건 중 빠진 것부터 확인한다. 상태가 있는 기능은 초안·저장 실패·이탈·재진입 정책처럼 실제 행동이 달라지는 항목도 확인한다. 모든 항목을 설문처럼 채우지는 않는다.
- 기획자 에이전트에 위임할 때는 원래 요청·관련 자료·이미 받은 답변을 전달한다. 기획자는 모호점과 추천 질문을 주 세션으로 반환하고, 주 세션이 사용자에게 질문한다. 사용자 답변을 가정해 인터뷰를 완료하거나 에이전트끼리 승인을 만들어내지 않는다.
- 원래 요청, 사용자가 확정한 사항과 답변 근거, 조사로 확인한 사실, 제안/가정, 미정 결정을 구분한다. 제안·추천·기존 코드·무응답은 사용자 선택의 근거가 아니다. 목표·범위·성공 기준을 바꾸는 결정은 답변을 기다린다. 그 결정에 의존하지 않는 조사는 계속한다.
- 실제 인터뷰를 시작하면 `.proofstill/work/intake-<작업ID>/brief.md`에 현재 정제 상태와 다음 질문만 짧게 유지한다. `init`이 만드는 개발 작업 폴더와 구분한다. 대화록·별도 PRD·질문은행은 만들지 않는다. 계속 개발 근거로 쓰는 요구사항 문서는 보존하고 brief에는 변경분·다음 질문만 둔다. 중단·결정 대기 중에는 보존하고 재개 시 실제 답변·자료와 대조한다.
- 종료 조건은 개발 범위와 관찰 가능한 완료 조건을 정할 수 있고, 그것을 바꿀 미정 결정이 해소되었거나 사용자가 명시적으로 범위에서 제외한 상태다. 마지막 답변이 충분하면 짧은 정제 결과를 알리고 브리핑으로 이어간다. 모든 작업에 추가 승인 절차를 요구하지 않는다. 답변이 부족하면 미정으로 남기며 이에 의존하는 구현·기준 고정은 진행하지 않는다.
- 전달할 내용은 원래 요청, 확정 요구·제약·범위 제외, 관찰 가능한 수용 예시, 남은 결정과 영향이다. [개발 스킬](../proofstill-develop/SKILL.md)이 이를 작업 브리핑과 기능 정의로 옮긴다. `intent`에는 사용자 원래 요청을, `requirements`에는 확정된 요구를, `context`에는 제약·결정의 실제 답변 근거를 보존한다. 테스트의 상세 설계와 적절성 판정은 후속 개발·독립 검증에서 수행한다.
- 전달은 짧은 원문 참조와 확정·미정의 변경분으로 한다. 이미 기록된 내용을 다시 풀어 쓰지 않는다. IA·상태는 필요할 때 흐름·유지·임시·예외 몇 줄로 붙이며, 결정 근거나 중요한 미정 사항을 생략해 길이만 줄이지 않는다.
- 정제된 의도는 개발 브리핑을 거쳐 [UX 디자이너](../proofstill-ux/SKILL.md)에게 넘긴다. UX 인터뷰에서 확정한 상태·행동·실패/복구 정책은 상태머신 계약과 실제 Trace로 이어지게 한다. UX의 화면·상태 흐름에 필요한 정책이 미정이면 해당 질문만 인터뷰로 돌려받는다. 기획자가 상세 화면 설계까지 중복 작성하지 않는다.
- 새 프로젝트나 중요한 기술 변경의 구현 가능성·아키텍처·스택·폴더 구조에 관한 결정은 [시니어 개발자 인터뷰](../proofstill-engineer/SKILL.md)로 이어간다. 기획 인터뷰 완료를 기술 선택 완료로 간주하지 않는다.
- 확정 내용은 기능 정의와 검증 증거로 이어지게 한다. 변경되는 임시 인터뷰 파일을 고정 검토의 `context_files`로 직접 연결하지 않는다. 개발 완료·결과 전달 후 해당 intake 폴더의 인터뷰 소유 brief만 제거한다. 인터뷰 자체는 CLI의 자동 단계나 권한 차단기가 아니라 에이전트가 따르는 절차다.
