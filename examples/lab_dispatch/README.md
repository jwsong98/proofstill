# LINKLAB 실험 패키지

사용자 제공 통근버스 예시에서 ‘복합 배정, 업무 의미 발견, 데이터 변경, 결과 검증’의 구조만 참고한 새 창작 문제입니다. 실제 문제 원문과 예시 구현 결과는 복제하지 않았습니다.

- `participant/`: 참가자에게 제공할 의뢰서·파편 문서·합성 CSV. 이 폴더만 개발 프로젝트로 사용합니다.
- `facilitator/`: 담당자 역할과 확정 정책, 검증용 실현 가능 계획. 연습 중 참가자/개발 에이전트의 입력에 넣지 않습니다.
- `generate.py`: 고정 규칙으로 CSV와 비공개 실현 가능 예를 재생성합니다.
- `verify.py`: 입력의 참조·실현 가능 예를 확인하고 잘못된 계획을 거부하는 검사입니다. 참가자의 최적화 구현이나 자동 채점 서버가 아닙니다.

원본 패키지에서 participant 폴더와 facilitator 폴더를 구별하는 것은 스포일러 방지를 위한 관례입니다. 같은 계정의 로컬 파일 접근을 보안적으로 격리하지 않습니다. 실험용 별도 복사본을 이용하고 개발 에이전트에게 참가자 폴더 밖의 정답/진행자 자료를 읽지 않도록 명시하세요.

생성/검사: `python3 examples/lab_dispatch/generate.py`, `python3 examples/lab_dispatch/verify.py` (저장소 루트 기준). 생성 명령은 패키지의 생성 CSV와 witness를 다시 쓰므로 참가자 작업 사본에 실행하지 않습니다. 의뢰서와 운영 정책은 생성기가 덮어쓰지 않습니다.

실습의 난도는 업무 규칙의 발견과 일정의 일관성에 있습니다. 전역 최적해를 요구하지 않으며 자동 점수는 제공하지 않습니다. 담당자가 공개한 조건을 참가자가 실제 근거로 기록한 뒤 자기 구현과 별도 검사를 연결하는 것이 하네스 실험 대상입니다. 이 패키지가 검증되어도 참가자가 앞으로 만들 제품이 검증된 것은 아닙니다.

검사 범위: verify.py는 이 문제의 입력과 비공개 계획의 실현 가능성만 확인합니다. 참가자 JSON 내보내기 형식·지표·데이터 해시·게시/로그인/DB/탐색 중단 의미를 채점하지 않습니다. 이 항목은 참가자가 구현하고 별도로 검증할 과제입니다.

## 별도 실험 만들기

기존 로컬 콘솔이 실행 중일 때 다음 명령으로 새 실험 사본과 두 프로젝트를 만듭니다. 기존 디렉터리는 거부합니다. 담당자는 로그인된 Codex를 사용하며 별도 API 키를 요구하지 않습니다.

```sh
python3 examples/lab_dispatch/launch.py --destination ~/Proofstill-Labs/linklab-01 --console-url http://127.0.0.1:7777
```

콘솔 없이 파일만 준비하려면 `--console-url`을 생략합니다. 나중에 같은 대상에 `--resume --console-url http://127.0.0.1:7777`을 붙이면 기록한 단계부터 등록합니다. 등록 실패 시에도 복사본과 진행 기록을 보존합니다. 다른 콘솔 DB로 바꿀 때는 새 실험을 만드세요.

콘솔에서 `LINKLAB · 참가자`는 제공 원문을 읽고 구현하는 곳, `LINKLAB · 담당자`의 `김도윤 선임 · 업무 문의`는 질문하는 곳입니다. 두 프로젝트 사이의 답변·근거는 자동 복사되지 않습니다. 읽지 않은 답변을 이미 확인한 근거로 선등록하지 않습니다. 생성 명령이 인사 요청을 수락받았다고 대화 성공을 뜻하지는 않으므로 세션의 실제 응답을 확인하세요. 실험 사본에는 비공개 witness와 검사 코드를 복사하지 않습니다.

실행 중 강제 중단이 API 생성 성공 직후·로컬 상태 저장 직전에 발생하면 재개 시 근거가 중복 등록될 수 있습니다. 정상 재개는 실제 콘솔에서 중복 없음으로 확인했으며 장애 주입은 하지 않았습니다. 원문 검토 중 중복이 보이면 같은 출처인지 확인하세요.
